# 设置页汉化信息

设置列表在“示例作品”之后、“删除全部数据”之前新增“汉化信息”。弹窗沿用原版橙色边框、上屏说明和下屏双选项；“本项目”显示作者 LITTOMA、项目地址与 MIT 许可，“第三方”显示思源黑体、缝合像素体、libkwz 和完整许可说明的位置。选择项目时立即更新上屏说明；关闭、取消或 B 键返回设置列表，不写入设置值。

## 维护入口

- `overlays/zh-CN/settings/texts.json`：新增署名文字的唯一来源。原有消息仍由 `translations/` 维护。
- `src/SettingsAbout/about.c`、`hooks.S`、`link.ld`：固定 v7.2.0 的原生调用与拦截。
- `src/SettingsAbout/author.py`：从用户 CIA 只读取相关资源，编译小型 ARM 扩展并重建补丁配方。所有中间文件位于独立 `.work/settings-author-*`，正常完成或异常退出均清理。
- `overlays/zh-CN/settings/*.bclyt.json`、`*.bclan.json`：复制原资源片段和插入少量修改字节的配方，固定原始与结果 SHA-256，不分发完整原版布局。

正常构建只需现有 .NET 工具，无额外依赖。修改署名或原生源码后，先编译构建工具，再用 Python 3 和具有 ARM 后端的 Clang/LLD 重新生成配方：

```sh
python src/SettingsAbout/author.py --input /path/to/original.cia
```

可通过 `--clang`、`--linker` 指定 LLVM 路径；没有指定 LLD 时，先从 PATH 查找，再使用 Clang 同目录的 LLD。作者工具不依赖 Ghidra、Capstone 或 Windows API。生成后运行 `plan`、`selftest`、`build`。正常构建检查所有署名字符的字库覆盖，检查文字是否包含在实际代码补丁中，并核对四份作者源码的 SHA-256；源码改变而未重新生成配方会报错。

## 原生实现依据

Ghidra 只读分析与 ARM 指令核对确认以下 v7.2.0 地址（程序基址 `0x100000`）：

| 地址 | 用途 |
|---|---|
| `0x186730` | ConfigMenu 点击事件；仅拦截新增 `About` 名称 |
| `0x186164` | 设置弹窗轮询；仅对原版未使用的场景状态 9 分流 |
| `0x185EDC` | 设置初始化后填写新增行标题 |
| `0x22A748` / `0x22A86C` | 原生设置弹窗打开 / 关闭 |
| `0x21E8CC` | 原生 UTF-16 文本设置与布局刷新 |
| `0x230E68` / `0x230E34` | 原生确认 / 取消检测 |
| `0x1BE000..0x1BEA24` | ConfigMenu 的按钮名称表、索引上限及滚动长度 |

按钮名称表从 9 项增加到 10 项，未选择哨兵值由 9 改为 10。原有按钮索引不变。原版场景状态 7/8 的删除确认流程不变；汉化信息使用独立状态 9，调用原生关闭逻辑但不调用任何设置写入或删除功能。

布局复制原版完整宽度按钮的五个控件、五个材质，以及六个动画里的对应轨道，使用独立名称，避免高亮影响原有按钮。滚动末端从 288 增至 350，原有删除按钮下移 62，其他现有控件逐字节保持。CLYT 分组的名称与成员字段都是 16 字节；BCLAN 的对象名称是 20 字节，二者不可混用。

新增代码与只读文字位于 `0x373300` 开始的空余文本页，必须在 `0x374000` 前结束；选择状态仅使用 BSS `0x448B1C` 的 4 字节。扩展头更新实际文本长度和 BSS 长度，文本页数不变，继续使用 64 MiB 模式和已验证的主堆 / 资源缓存划分。

## 验证范围

回归检查覆盖原有控件保护、独立材质、布局层次与索引、全部六个动画的原轨道保留、新增轨道复制、原生代码与文本来源一致性、补丁越界/混合片段/结果哈希拒绝，以及内存页数与新增状态长度。

在独立 Citra Nightly 2104、旧款 3DS 配置中验证了进入设置和原有工具箱弹窗的打开/取消；用户随后确认新增功能没有问题。之后完成 CLYT 分组字段长度修正，并以结构回读及回归验证最终资源，未再次进行界面操作。实机尚未验证。构建、回读与确定性检查结果记录在 `artifacts/`，不将这些静态检查等同于实机运行。
